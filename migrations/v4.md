# v4

Project-side changes from v3 to v4. The skill `migrate` applies them in this order. No step needs a user answer.

v4 adds group folders (`DEV/<group>/<project>/`). A project on v3 stays where it is; the steps below only stop it from assuming that `DEV/` is its parent folder. Moving a project into a group is a separate task the user asks for, not part of `migrate`.

## 1. `scripts/check.sh`: find `DEV/` by walking up

After the `cd "$(dirname "$0")/.."` line, add the `DEV=` block from `_template/scripts/check.sh` (the `while` loop that walks up to the directory that holds `_template/` and `.claude/skills/`). Skip when a `DEV=` line is already there.

Then replace every path that reaches `DEV/` by counting parents with `"$DEV"`:
- `../_tools/` → `"$DEV/_tools/`
- `../scripts/` only when it means DEV/scripts. Check first: a `../scripts/` written from a project subfolder (`app/`) usually means the project's own `scripts/`, which stays as it is.
- a `cd ../../_tools` or `cd ../../scripts` written from a subdirectory → the same `$DEV` form

Leave paths that stay inside the project (`app/`, `dist/`, `scripts/` of the project) as they are. Read each changed line and confirm it still names the same file.

## 2. `scripts/check.sh`: header comment

Replace `(see ../CLAUDE.md, "Work loop")` in the header with `(see DEV/CLAUDE.md, "Work loop")`. Skip when the text is not there.

## 3. `CLAUDE.md`: first paragraph

Replace the sentence `The shared rules in \`../CLAUDE.md\` apply here.` with the one from `_template/CLAUDE.md`: `The shared rules in \`DEV/CLAUDE.md\` apply here; Claude Code reads every \`CLAUDE.md\` up the folder chain, including a group's.` Keep the rest of the paragraph. Skip when the project wrote its own wording that does not name `../CLAUDE.md`.

## 4. `CLAUDE.md`: version line

Set `Harness: v4` (`migrate` step 6 does this last).
